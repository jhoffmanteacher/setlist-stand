## Writing code here (service worker, updates, install)

Each rule is a real bug the closed loops found.
1. **Never hand-edit `VERSION` or the `HASHES` table in `sw.js`.** `node tools/checks.mjs --bump` writes both; the check fails when a precached file changed and VERSION did not, and when the table is not exactly right for the files (a stale table is expected while you work and refused at a push to `main`). `--rehash` writes the table only, for scratch copies.
2. **A new or renamed app file goes into `PRECACHE`** (checks fail otherwise); a file that 404s at install makes the whole install fail, so the old version keeps running: that is the safe failure, keep it.
3. **An update waits for a tap on "Updated. Tap to reload".** Never reload on `controllerchange` unless this tab's banner was tapped (`asked`); the first install fires `controllerchange` too. It also waits while a restore or backup box is open (`body.busy`, set by `busy()` in `js/util.js`; the banner is hidden then). Only the tapped tab reloads; the open song comes back (`ss-resume`). The kill switch's `ss-sw-killed` message is the one other reload.
4. A change here: run `node tools/loops.mjs --only update`, `--only offline`, `--only kill`. A worker that strands tablets is fixed with `BREAK-GLASS.md` (b), not by a quick second push.

5. **`js/boot.js` stays a classic script loaded first with `defer`** (2026-11-23). `js/main.js` never imports it; they share only `window.ssBoot` (`main.js` registers the worker itself only when it is missing). It must keep working when a module of the app fails to load: that is how a broken deploy is replaced. The registration, the banner, the controllerchange rule and the `ss-sw-killed` reload live there, not in `main.js`. `tools/checks.mjs` ("boot script first") pins it.
6. **A missed file is never stored; `heal()` refills only for the same VERSION** (2026-11-23). Another site on the same origin (guitar-class did, until fixed) or the browser can delete this app's cache. The worker fetches a missing file but does not put it in the cache (a file of a newer deploy must never land in an older version's cache). `js/boot.js` asks for `ss-heal` whenever the app is on screen, online and nothing is open; `heal()` checks the server's `sw.js` VERSION, fetches every missing file, refuses the lot on a failed, redirected or wrong-type answer, then stores all or nothing.
7. **The banner and the update check wait while anything is open**: a song, the splitter, a busy box or any dialog (`quiet()` in `js/boot.js`). An update check runs at most hourly.
8. **A stored app file is used only after its bytes are checked** (2026-11-24). Cache Storage belongs to the whole `github.io` address: a script on another site there can put its own `js/googleauth.js` in this app's cache and take the Drive token at the next sign-in. `sw.js` holds `HASHES` (SHA-256 of every `PRECACHE` file; the browser keeps `sw.js` outside Cache Storage, so a page cannot change it). `fetch` answers from the cache only for a path in `PRECACHE` (a `?query` is ignored; any other path goes to the network), only when the stored bytes hash to the table, with a NEW `Response`: status 200, the worker's own `Content-Type` (`TYPES`), no stored header (a stored entry can carry `Refresh` or a CSP). Checked on every use, no remembered verdicts. A failing entry (and its `?query` variants) is deleted, the page gets `ss-bad-file` (js/main.js writes one quiet Problem log line, best effort), and the answer comes from the network, not stored. `heal()` treats a failing stored file as missing and stores a fetched file only if it matches; `install` fails (the old version keeps running) when a stored file does not match, after deleting what failed (another page can write into the cache of the NEXT version, whose name is a date; in Safari's engine an entry stored under a `Vary` header is not replaced by `addAll`, and would fail every later try). A stored file that cannot be READ right now is not used but not deleted either (`unreadable`); only bytes that were read and differ are deleted. The hashes are of the COMMITTED bytes: `.gitattributes` has `* -text`, and `checks.mjs` asks git whether it would convert any served file and whether a served file is CRLF on disk but LF in git (a Windows checkout from before `.gitattributes`; git status stays clean then); `--bump` refuses in that state. Offline with a failing file the app may not open until it has been online once (same sign as (g) in `BREAK-GLASS.md`). A test deploy that changes a file in a scratch copy writes the table again (`makeSiteCopy` does after `mutate`; `plant-faults` does). `--only filecheck` proves it; the planted faults are the `filecheck-*` ones.
