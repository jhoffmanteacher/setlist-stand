# Which loop to run after which change (moved verbatim from CLAUDE.md, 2026-11-23)

At most two browser runs at a time (see "Don't overload Jonathan's Mac" in `CLAUDE.md`).

| Changed | Run after (at most two browser runs at a time, see above) | What it closes |
|---|---|---|
| `js/backup.js`, restore or backup format, `putAll`, record shapes in `js/store.js` | `--only roundtrip` | backup -> wipe -> restore gives back every record and every PDF byte; v1 backups upgrade; a damaged or interrupted restore changes nothing; the converter output equals the MobileSheets backup it came from |
| `js/print.js`, `js/downloadall.js`, `js/crop.js`, crop or text-note drawing in `js/ink.js` / `js/viewer.js` | `--only print` | the printed PDF, rendered again with pdf.js, has marks, notes and crops where the viewer shows them, on rotated pages too; the PDFs inside a Download all zip, read back in Node, equal each setlist's own Download PDF (names with the gig date and " (2)", empty setlists skipped, entries stored, a left-out chart named, the size refusal, the library unchanged) |
| `sw.js`, `js/boot.js` (registration, update banner, update checks, the refill), `js/main.js` (resume), `manifest.webmanifest`, any precached file added or renamed | `--only update`, `--only offline` and `--only filecheck` | first install never reloads; an update waits for a tap, reloads once, puts the open song back, keeps the library; a broken deploy keeps the old version; the whole app, print and backup work with no network; a stored file another site replaced is never run or served (see the next row) |
| `sw.js` (the byte check in `fetch`, `install` and `heal()`, `HASHES`, `TYPES`), `tools/checks.mjs` (`--bump`, `--rehash`, the table checks), `.gitattributes`, the `ss-bad-file` line in `js/main.js` | `--only filecheck` (and `--only update`, `--only offline`, `--only kill`, `--only viewer-hardening`; `--only live` after a deploy) | with the cache changed from a page the way another site could: a replaced `js/googleauth.js` (and a file the page has not asked for) never runs, the Problem log names both, the refill puts the server's bytes back (online, and offline once one online visit has happened); a replaced `index.html` or folder entry is never shown; right bytes with a `Refresh`, CSP or wrong `Content-Type` header reach the page with none of them and the worker's own type; an entry for a path that is not in `PRECACHE` or under `?query` is never served; a server that sends other bytes is `refused` and nothing is stored; a deploy whose file does not match its table fails the install and the old version keeps working (WebKit too, no CDP) |
| anything users do in the library, setlists, ink, crops or notes | `--only model` | seeded random action sequences agree with an independent model, after a reload and after a backup round trip |
| `tools/kill-switch/kill-sw.js`, the `ss-sw-killed` message handling in `js/main.js` | `--only kill` | armed, the emergency worker empties the cache, the open tab reloads once and the library is untouched; disarmed, the real worker and offline come back |

| `js/viewer.js`, `js/ink.js` (gestures), `js/print.js` (encrypted, bad points), `sw.js` install, `js/main.js` update tracking, `js/util.js` dialogs, `css/app.css` colours, setlist drag | `--only viewer-hardening` | a page turn never moves a stroke, a locked PDF is named and never printed blank, a deploy installs the new files, dialogs behave on Enter, colours have fallbacks |
